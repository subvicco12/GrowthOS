# Session 02 independent disposable workflow proposal (017)

Review-only for deployment. This proposal depends only on approved baseline 001–009, **not** on candidates 010–016. It is not registered with a production migration runner. Installing it in a disposable test database does not approve it for staging or production.

The new tables store expiring ownership challenge hashes, connector drafts without secrets, manual analysis jobs/input/results, immutable derived recommendations linked to the existing internal approval queue, and append-only workflow events. A separate contract marker prevents accidental use of an incompatible schema. Recommendation approval updates the existing queue and its immutable decision history; it grants no publishing authority.

Use only a fresh MariaDB 11.8 test schema, named `growthos_test_*`, on loopback. Apply approved 001–009 using the existing disposable runner, then explicitly invoke `node scripts/install-session02-disposable.cjs` with `GROWTHOS_SESSION02_DISPOSABLE=YES`, `GROWTHOS_TEST_DB_DISPOSABLE=YES`, and isolated DB configuration. The installer refuses partial installs. Discard the container/schema after test failure rather than blindly replaying DDL. No production installer, upgrade path, grants package, backup/restore proof, or database approval is supplied by this proposal.

Runtime APIs also require both disposable opt-ins, loopback DB host and a test schema name; otherwise they return `ISOLATED_SCHEMA_REQUIRED` without opening the pool. Do not set these flags for production. Missing schema must remain an unavailable state, not trigger automatic DDL or fall back to tables from 010–016.

Ownership verification requires an exact operator `GROWTHOS_OWNERSHIP_ALLOWED_HOSTS` entry. The transport allows only a fixed HTTPS/443 well-known file, pins a validated public IPv4 DNS answer, rejects redirects/compressed bodies/private or reserved addresses, validates TLS, and caps work at 8 seconds/16 KiB. IPv6-only hosts are unavailable. Proxy-only environments fail closed until a separately approved pinned proxy transport exists; the adapter does not bypass the inherited proxy. External ownership/network behavior has not been certified against a live site.

Analysis jobs execute finite, deterministic processing of user-supplied, **unverified** observations. No URL is fetched, no paid service is called, and external spend is exactly zero. The service enforces 20 jobs/site/24h, maximum 3 attempts, internal approval before run, explicit due times, cancellation, current tenant roles, website pause/archive, and a feature-shutdown audit watermark. A later shutdown invalidates earlier jobs. There is no autonomous scheduler or background dispatcher: an authorized administrator manually runs a due job. Each run stores at most 100 derived recommendations; the result explicitly records this cap. Recent UI windows are limited to 25 jobs, 100 recommendations and 50 events; unlimited/paginated history is unfinished.

Review requirements include schema approval, quota/grant policy, retention and privacy for supplied research, populated upgrade/backup/restore, proof expiration/revocation policy after successful ownership verification, production-grade outbound proxy support, full job/event pagination and separately authorized worker design. Keep production release on HOLD.
