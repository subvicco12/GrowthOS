# Session 03 isolated runtime proposal 018

**Review/testing only; no production activation.** See `RECONCILIATION_REVIEW.md` for the separate static review of overlapping 010–018 concepts, hashes, dependencies and the proposed production reconciliation process.

This additive schema requires approved 001–009 and the unchanged isolated proposal 017. In a fresh disposable MariaDB 11.8 schema only, explicitly install 017 with its existing installer, then invoke `node scripts/install-session03-disposable.cjs`. Both runtime and installer require `GROWTHOS_SESSION02_DISPOSABLE=YES`, `GROWTHOS_SESSION03_DISPOSABLE=YES`, `GROWTHOS_TEST_DB_DISPOSABLE=YES`, a loopback DB host and a `growthos_test_*` name. No startup installer or production migration registration exists. Abandon partial schemas; never replay partial DDL or install 010–016 as a shortcut.

`GROWTHOS_DEV_CONNECTOR_KEY` must be an operator-provided random 32-byte lowercase hex key kept server-side, not a `NEXT_PUBLIC_*` variable or committed file. Synthetic enrollment generates a server-only credential encrypted with AES-256-GCM and tenant/site/connector/authority-epoch/endpoint AAD. Plaintext credentials and lease tokens are never returned by operations APIs. Re-enrollment rotates the credential and rejects old in-flight health replies. The only health adapter is a signed, nonce-bound local simulation with a one-second bound; it has no DNS, HTTP, WordPress or socket path. Its status is explicitly `synthetic_healthy`, never live connector health.

Successful scoped ownership proofs create a seven-day authority grant. Current grants are required on enrollment and both sides of health checks. Explicit revocation and expiry cleanup revoke enrollment, clear legacy ownership/switches, and increment a durable stop fence. Each bounded worker cycle applies expired ownership before recovering or claiming work; read-only views calculate expiry without mutating data. Revoked/historical grants cannot unlock metadata editing for a previously verified website.

Run the optional background entrypoint manually with `npm run worker:synthetic`, explicit `GROWTHOS_WORKER_ORGANIZATION_ID`, `GROWTHOS_WORKER_WEBSITE_ID`, and `GROWTHOS_WORKER_ACTOR_ID` (a current owner/admin). The worker revalidates membership in the DB, not the environment's identity claim. `GROWTHOS_WORKER_ITERATIONS` defaults to 1 and is bounded at 60; `GROWTHOS_WORKER_INTERVAL_MS` defaults to 1000 and is bounded to 100–5000 ms. SIGINT/SIGTERM stop new claims; no daemon, cron, cloud schedule or paid service is registered. Browser controls can execute a single isolated cycle or recover expired leases.

Each claim has a 30-second lease, hashed random token and monotonic fence. Heartbeats and commit recheck role, lease, approval/revocation, website state and stop watermark. Dead workers recover after expiry into 5/10/20-second backoff with at most three attempts. Old tokens cannot commit after recovery/cancellation; queue scanning retires permanently stopped jobs rather than starving newer work. Finite synthetic analysis permits no outbound calls or paid AI spend, and recomputes/validates the result at commit. Existing 20-job/site/day admission limits are preserved. General paid-provider reservations, worker fleets and live publication authority remain out of scope and disabled.

`GET/POST /api/isolated-operations` supplies tenant/site-scoped operational summaries and stable 25-record keyset pages for jobs, recommendations, audit events and attempts. Cursors bind organization, website, stream, microsecond position and ID; they are untrusted position hints, not authorization. No encrypted credentials or lease tokens appear in these views. Immutable revocation/worker history augments existing append-only workflow events. Full source observations stay in the existing scoped research workspace; monitoring exposes source labels/times/hashes with unverified-manual provenance.

Production gates remain HOLD: independent schema/grants/backup-restore certification, trusted external ownership/connector authority, live read-only WordPress certification, key rotation/recovery custody, paid quota integration, deployment authorization, load/fault testing and canonical migration reconciliation. None is waived by disposable/synthetic test passes.
