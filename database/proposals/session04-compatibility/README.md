# Session 04 isolated compatibility proposal 019

Review and disposable certification only. This additive contract requires approved 001–009 plus unchanged isolated 017/018. It neither installs 010–016 nor promotes development authority. `install-session04-disposable.cjs` requires all four disposable opt-ins, a loopback host, a growthos_test_* schema, MariaDB 11.8 and the prior version marker. Existing/partial installs are refused; no production/startup registration is supplied.

The compatibility inspector checks the nine baseline ledger hashes, isolated version markers, required tables/columns, engines, matching inherited collations, critical indexes, composite scope foreign keys and immutable-history triggers. Missing or incompatible state fails closed. Canonical authority and production readiness are explicitly unavailable; production contract certification is not inferred from local metadata.

`GrowthOSReviewBundle/v1` exports scoped manual research with source hashes and original observation times, and internal approvals/immutable decisions/revocations with actor IDs, original IDs, request keys and timestamps. Strict validation rejects unknown fields and trust upgrades. Ownership, issuer grants, credentials, synthetic/fixture health, leases and spending authority are never exported. The export is limited in size/record count and never truncated silently.

The review-bundle CLI validates, exports to a new private file, stages into quarantine using an idempotency key, and reverses only that quarantine batch. Staging does not create canonical evidence or executable approvals. Reversal removes quarantine items and retains an audit receipt; immutable source decisions and research remain unchanged. No canonical import, destructive rename, automatic upgrade or trust promotion path exists.

The separate database certification script creates only fresh disposable target schemas, tests read-only grant denials and a cross-tenant FK refusal, dumps populated application data through a limited backup account, restores to an empty target and compares complete row hashes, engines/collations, indexes, FKs and triggers. It also tests adding 019 to a populated 017/018 clone, refusal of interrupted DDL, and recovery into a fresh schema rather than replaying partial DDL. Private backups are deleted after verification. This is a logical application-database rehearsal, not a production backup/restore or WordPress-database certification.

Fleet controls default to stopped and zero spend. An explicit tenant administrator can resume local workers only. Emergency stop advances durable website fences. Session 04 workers compare their clock with database UTC (5-second maximum skew) and check stored zero-spend/external-disabled policy at execution authority fences. Prior Session 1–3 modes remain isolated and are regression-tested without the Session 04 flag; that compatibility mode does not authorize external providers.

The WordPress adapter is disabled outside explicit disposable configuration and accepts only the operator-fixed 127.0.0.1:33320 fixture endpoint. Credentials use a separate table and AES-GCM binding prefixed wordpress_fixture, never the synthetic or production trust namespace. Enrollment is resumable while pending, rotation advances revision, health uses signed fresh nonces, and revocation fails closed locally even if the fixture does not acknowledge. The fixture plugin is disabled unless GROWTHOS_READONLY_FIXTURE is explicitly defined; it offers health:read only, encrypted server-side credentials, nonce replay refusal, and no publication routes. Fixture-admin headers are a disposable test mechanism, not production enrollment authorization. Real WordPress fixture connectivity is labelled wordpress_fixture_healthy and productionTrusted=false.

Production remains HOLD pending independent canonical migration approval, true issuer/domain authority, proxy-aware public TLS transport and enrollment, hardened production key custody, real provider budget reservation/settlement, fleet deployment/load/clock certification, populated production-like grants/backup/restore and independent release sign-off. Local artifact observations remain origin-unverified and do not measure live SEO rankings, competitor performance or revenue.
