# Quota and settlement persistence proposal v1 — separate review required

Status: NOT INSTALLED. Production HOLD / NO-GO. This proposal does not allocate a migration number or modify certified migrations. Reconcile numbering with the separately reviewed Work B persistence migration before writing DDL.

## Contract and accounting decisions

`src/core/quota-periods.ts` and `src/core/quota-settlement.ts` define a new, unwired contract. They do not change `mysql-budget-store.ts`, its non-UTC refusal, reconciliation, publication claims, approval authorization, cost reporting or any provider integration. Existing recorded costs remain recorded reservation accounting, not provider-billed spend.

Explicit site IANA timezone and reviewed runtime IANA rules version are mandatory. Local Monday midnight and the next local Monday are resolved to UTC; skipped or repeated Monday midnight is refused. DST can produce weeks shorter or longer than 168 hours. Offsets are sampled around the boundary, candidates are checked against local calendar fields, and exactly one midnight must exist. Unsupported offset names and missing/unknown zones are refused. Store the resolved zone, rules version, local Monday and both UTC boundaries. Pin Node/ICU/tzdata in release infrastructure; rules-version drift refuses accounting rather than reinterpreting history. Alias names normalize through Intl. Changes of zone/rules while periods overlap are refused, including after cancellation. A timezone change must wait for a nonoverlapping period or a separately reviewed audited conversion.

Portfolio months remain the reservation's UTC calendar month. Monetary postings, including late settlements/refunds, stay attributed to that original month; financial invoice-date reporting is a separate, unimplemented view. Site and portfolio limits use the same explicit currency. No currency conversion, implicit USD or floating-point amounts. Domain values are bigint, individual amounts are unsigned BIGINT-compatible, sums use unbounded bigint. Wire/database serialization must use decimal strings, never JSON numbers or Number coercion. Currency changes within an existing portfolio month are refused.

Reservation atomically holds capacity and estimated money. Start marks chargeable execution exactly once; the trusted execution handler must persist this event before any potential chargeable dispatch. Unknown dispatch retains the executing state and conservative hold, and cannot be cancelled/retried automatically. It is not evidence that a provider actually accepted a request. Pre-dispatch cancellation/expiry release capacity and money only through an explicit transition; an expired row conservatively holds resources until processed. Starting after expiry, with changed period, kill switch or reduced limits is refused. A new-week retry requires a new reservation and fresh authorization.

Completion/failure after start retains consumed weekly units. Charges are trusted, individually evidenced debits. Until a verified final gross settlement, hold `max(estimate, charges-refunds)`. Failed/completed but unsettled executions retain that hold. Final settlement must equal all recorded gross charges and releases unused estimate. Verified credits cannot exceed their referenced charge minus prior credits. Refunds never restore weekly units. A verified overrun is recorded and pauses new execution/reservations; neither refund nor settlement automatically clears the pause. Later contradictory charges after final settlement are refused pending operator incident recovery. Uncertainty never automatically releases funds or restarts execution.

Cancellation after start and reset of terminal states are prohibited. Failed-before-dispatch work uses cancellation, with an audit reason recorded by the adapter. There is no refund of a charge without issuer evidence. Approval of an internal decision does not authorize a charge or publication.

## Transaction, authorization and recovery obligations

Implement `AccountingStore` only with one database transaction spanning fresh authorization, org budget lock FIRST, site/policy locks next, scoped reservation CAS, unique event/posting inserts and append-only audit. Locks for different sites in the same portfolio MUST serialize on the same org budget row. Query all reservation types/sites for the original UTC month and all started/held capacity for the applicable site/content/week. All monetary changes and pause decisions commit together. Load only that organization's ledger; foreign rows are rejected by the domain service. A production adapter should use scoped indexed aggregates instead of loading an unbounded in-memory ledger, while maintaining equivalent semantics.

`authorize(scope, serverNow, operation)` must re-read active membership/session revocation, organization/site ownership, role and operation-specific permission, policy/currency/rules version, disabled controls and budget availability inside the lock. Reserve/start require permitted job kind, approval/version binding and fresh connector evidence where applicable. Financial reconciliation requires a separate service permission; human membership alone does not authorize charges. Return a membership/policy revision and a bounded authorization snapshot (checked time <= server now < expiry; at most five minutes). The domain rejects missing, future or expired grants even if the adapter returns a policy. No cached caller role, caller-supplied now, tenant ID, verified flag or idempotency key substitutes for these checks. Missing policy/database state refuses execution.

`verifyEvidence` has NO default implementation. Verify issuer registry/revocation, cryptographic signature, freshness, currency, original charge, exact org/site/reservation and entire operation payload. Canonicalize issuer identity before claiming a globally unique evidence ID. The test verifier is synthetic, not provider attestation. Verification failure must roll back everything. Authorization is checked again even for event replay; financial replay performs no new mutation.

New tables require separately reviewed immutable-journal/identity/terminal-state triggers and least-privilege grants. Runtime cannot update/delete journal rows or reset charged/terminal flags; installer credentials are separate and never used at runtime. Domain code cannot enforce grants or crash durability by itself.

Deadlocks/lock timeouts: roll back the entire transaction; bounded retry with the SAME event/reservation/evidence IDs, fresh authorization and comparison. Lost response: exact replay reads committed state. Interrupted transaction: no partial journal/aggregate result may survive. Unknown provider outcome: retain hold; use a trusted status probe, not a second dispatch. Corrupt ledger/negative net/currency mismatch must refuse and alert. Preserve failed evidence separately without converting it to an accepted posting. Failures to persist a known charge must create an operational incident through a separately reviewed recovery mechanism.
