## Job operations and recovery

No worker or dispatch is implemented. The independently acquired lease must remain valid through SQL COMMIT; a SQL witness generation/lease column is a diagnostic reference, **not** a substitute for the independent anchor. Before a claim, recheck current session, original approver, content hash/version, exact destination revision/target, feature/global pause, connector signed evidence, policy and distinct v2 funding. After claim, only signed read-only status probes may advance the same immutable claim. Unknown outcomes retain claim and funding hold, never schedule another publish. The fifth failed/unknown probe requires operator review. A duplicate claim/funding/auth use or rollback must not persist any partial job/event/charge. An indeterminate commit permits exact-identity readback and then operator HOLD, even if a read appears absent.

The read-only `MySQLPublicationJobRecoveryReader` inspects scoped job, event, binding and funding rows and refuses inconsistent scope, version, destination target hash, journal sequence, witness reference, canonical claim hash and distinct legacy/v2 funding identity. It **always** returns `publicationAuthorized:false`; it neither verifies provider signatures nor reads an independent trust anchor, opens a transaction for mutation, changes data, publishes or retries. Its mocked SQL tests are not InnoDB proof. The write-side `PublicationJobStore` and `AtomicPublicationRepository` remain unimplemented until a reviewed transaction/fencer/quota implementation exists.

Scheduled jobs for a revised content version can coexist in history because uniqueness includes content version. The same-transaction invalidator must cancel and release all earlier *unclaimed* work under locks before accepting the revision; any claimed/ambiguous old job refuses revision. There is no database partial-unique active-job constraint in this proposal. This concurrency invariant is a **separate live certification gate**, and publication remains disabled until proven.
