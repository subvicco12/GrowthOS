# Disposable GrowthOS staging — preparation only

**Production HOLD / NO-GO.** This package has not been executed in this Work environment. It requires a fresh local Docker Engine/Compose, Node.js 22, OpenSSL, free digest-pinned Node 22 and MariaDB 11.8 images, and synthetic values. Never use production credentials or a preexisting database. No GitHub Actions or deployment.

1. In a future isolated machine, inspect image manifests and set `GROWTHOS_STAGING_NODE_IMAGE=node:22-bookworm-slim@sha256:<reviewed digest>` and `GROWTHOS_STAGING_MARIADB_IMAGE=mariadb:11.8@sha256:<reviewed digest>`. The images are fetched before runtime isolation; verify their source and actual image versions. Use a local Unix Docker context. Set `GROWTHOS_DB_NAME=growthos_test_<unique>`, `GROWTHOS_DB_HOST=127.0.0.1`, `GROWTHOS_DB_PORT=33317`, `GROWTHOS_DB_USER=synthetic_<unique>`, `GROWTHOS_DB_PASSWORD=synthetic_<random>`, `GROWTHOS_STAGING_ROOT_PASSWORD=synthetic_<different random>`, `GROWTHOS_STAGING_USER_PASSWORD=synthetic_<different random>`, `GROWTHOS_TEST_DB_DISPOSABLE=YES`, and `GROWTHOS_MIGRATION_TEST_DISPOSABLE=YES`. Keep values in a private process environment, never a repository file or command log. Do not reuse credentials.
2. Create a temporary directory at `staging/certs` and set `GROWTHOS_STAGING_CERT_DIR` to its absolute path. Generate a disposable local TLS certificate: `openssl req -x509 -newkey rsa:3072 -nodes -days 1 -keyout staging/certs/key.pem -out staging/certs/cert.pem -subj '/CN=growthos.test' -addext 'subjectAltName=DNS:growthos.test'`; then `chmod 600 staging/certs/key.pem`. Do not commit keys.
3. Pull the two reviewed digest-pinned images with `docker pull "$GROWTHOS_STAGING_NODE_IMAGE"` and `docker pull "$GROWTHOS_STAGING_MARIADB_IMAGE"`. Run `node staging/preflight.cjs`; it checks the local Docker context, image versions using containers with `--network none`, and the Compose port/network contract. It must exit 0 before `docker compose -f staging/compose.yaml build --pull`. Inspect the resulting image IDs and use `docker compose -f staging/compose.yaml up -d`. Recheck `docker compose -f staging/compose.yaml ps` and `docker inspect` for actual loopback bindings, private network and no published app port; stop if they differ. Confirm server identity/version and an empty disposable schema before any migration.
4. Run `node scripts/production-migration-executor-candidate.cjs --test-disposable` **once** on the fresh schema. It refuses nonempty or partial installation; never retry a failed partial DDL installation. Run `node --import=tsx staging/seed.mjs` once after all nine ledger hashes and 15 tables are verified.
5. Run `node staging/e2e.mjs` once. It rechecks preflight and database identity, uses the self-signed certificate as an explicit CA, and asserts HTTP and database state. The proxy is bound to host loopback, and the app has no published port. It does not assert external network ingress properties beyond this disposable Docker boundary. If any assertion fails, stop and retain sanitized evidence. Do not automatically retry, reset or delete data.
6. After recording evidence, stop only this named disposable project with `docker compose -f staging/compose.yaml down`; remove temporary certs and schema only after a separate review of the disposable identity. This procedure never targets production.

The fixture keeps both websites draft with automation and auto-publish flags false. Consequently the HTTP suite validates idempotent disable and the absence of false audit events; a true-to-false feature audit transition remains a separate gate that needs a reviewed safe synthetic fixture. The proxy must also be tested against the actual intended ingress topology before release. The optional environment from this document has not been created here.
